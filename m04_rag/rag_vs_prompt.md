# RAG 与 Prompt 技术的关系和区别

这几个概念其实处于**不同的层级**，不是并列关系。理清这一点后就很好理解了。

## 层级划分

**Prompt（提示词）** 是最基础的概念——你输入给大模型的指令文本。它是一个"容器"，而 zero-shot、one-shot、few-shot、RAG 都是往这个容器里放东西的不同**策略**。

```
Prompt（载体）
├── 按"示例数量"划分的策略
│   ├── Zero-shot（零示例）
│   ├── One-shot（单示例）
│   └── Few-shot（少量示例）
└── 按"信息来源"划分的策略
    └── RAG（检索外部知识注入）
```

## Zero-shot / One-shot / Few-shot 的区别

这三者是**一个维度上的连续谱**,区别只在于 prompt 中给模型看了多少个"参考例子":

**Zero-shot（零样本）**:不给任何示例,直接让模型做任务。
```
把下面这句话翻译成英文:今天天气真好。
```

**One-shot(单样本)**:给一个示例做参考。
```
中译英示例:
我饿了 → I'm hungry
现在翻译:今天天气真好。
```

**Few-shot(少样本)**:给若干个示例(通常 2-5 个),让模型从例子中"领悟"模式。
```
中译英示例:
我饿了 → I'm hungry
他在跑步 → He is running
她很聪明 → She is smart
现在翻译:今天天气真好。
```

核心思想是**in-context learning(上下文学习)**——模型不更新参数,纯粹从 prompt 里的例子中学规律。例子越多通常效果越好,但也会消耗更多 token。

## RAG 和它们不在同一维度

**RAG(Retrieval-Augmented Generation,检索增强生成)** 解决的是另一个问题:**模型不知道你的私有知识或最新信息**。

RAG 的流程是:
1. 用户提问
2. 系统从外部知识库(向量数据库、文档、网页等)检索相关内容
3. 把检索到的内容**塞进 prompt** 一起给模型
4. 模型基于这些"现查的资料"作答

例如问"我们公司去年的差旅政策是什么?":系统先去公司文档库检索相关条款,然后构造类似这样的 prompt:
```
基于以下公司文档回答问题:
[检索到的文档片段...]
问题:我们公司去年的差旅政策是什么?
```

## 关键区别总结

| 维度 | Zero/One/Few-shot | RAG |
|---|---|---|
| 解决的问题 | 让模型理解任务格式或模式 | 让模型获取它不具备的知识 |
| Prompt 里放什么 | 任务示例 | 检索到的外部资料 |
| 是否需要外部系统 | 不需要 | 需要(检索器+知识库) |
| 知识更新 | 改不了模型的知识 | 知识库一更新,答案就更新 |

## 它们可以组合使用

实际工程中这些方法**经常叠加**。比如一个客服机器人可能这样工作:RAG 检索出相关文档片段,同时 prompt 里再放 2-3 个 few-shot 示例教模型该用什么语气和格式回答。最终的 prompt 同时包含了"参考资料(RAG)"和"回答示范(few-shot)"。

一句话概括:**Prompt 是舞台,zero/one/few-shot 是教模型"怎么演",RAG 是给模型递"剧本资料"。** 它们解决的是不同的问题,可以独立用也可以一起用。
